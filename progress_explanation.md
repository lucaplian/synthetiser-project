Firstly, we tried to implement, seing that neural network algorithms such as CTGAN and TVAE Synthetizers take a lot of time to generate of time(around of time), we used GaussianCopulaSynthesizer, which is a faster alternative for generating synthetic data. We show that the synthetic data using gaussian distribution initially meaning that the extreme values were more overrepresented in , due to the nature of the Gaussian distribution, which cannot capture values that are in step descent.

That is why we used log trick that meant transforming the data using logarithmic scaling to reduce the impact of extreme values, which is then convert back to the original scale using exp. 

We initially did utility, fidelity, privacy and diversity tests using this model. The utility test consisted of a DiagnosticReport and QualityReport, which provided insights into the quality and characteristics of the synthetic data. The fidelity test involved comparing using a metric called AUPRC, which takes into consideration the unbalanced nature of the data, 75% of the data were zeros in our case, we tested using different models such as Logistic Regression, Random Forest, SVM, KNeighborsClassifier, and we computed the average AUPRC score across these models, and then we divided the AUPRC score of the synthetic data by the AUPRC score of the real data to get a ratio that indicates how well the synthetic data preserves the relationships present in the original dataset.

As for the privacy test, we used a metric called Distance Closest to Record (DCR), which measures the distance between synthetic records and real record, and then we used the minimum for each, to compute the score. The higher the score, the better the privacy. The second metric we used were the MITM for the synthetic and real data, which measures the loss in the train (real or synthetic) data and the test data, and then we divided them to get the ratio, the closer to 1 the better. We cap it to 1 if it is better. Then privacy is computed as the having a weight for 0.5 for DCR, and 0.25 for both MITM scores.

For diversity, we covered the across different columns: categorical, numerical and binary. For categorical columns, we 
used the value 1 and then subtracted with the sum of the differences between the frequencies of each dataset divided by the number of columns. For binary columns, the difference between ratio of one binary value, added them all up and then divided by the number of binary columns. For numerical columns, we calculated the difference for certain percentiles and its reverse one(eg. 5th and 95th percentile) between real and synthetic data, 
the we divided by the number of percentiles, and then added into another sum, which was the divided then into the number of numerical columns.

Then we computed the final score for diversity, which was weighted depending on the number of columns for each type, and then we divided by the total number of columns. 

We found that the gaussiancopula synthesizer was not a good metric for differential privacy, which was forcing us to use laplace noise to the data, which is not ideal, we tried to use the CTGAN and TVAE synthesizers, but the problem was that opacus dp library was not properly compatible with the synthetizers from SDV, so we tried to modify the library inside it to make it compatible, and we tried for 5 days to make it work, but we could not make it work, even though we solved all the errors, the synthetic data generated only values of 0, due to encountering a problem with the weight explosition, which is a problem for the TVAE, which uses an encoder and decoder arhitecture.

In the end we decided to switch to a different libary from synsynthizer, which uses diverse models such as DPCTGAN, MST and such. We used the DPCTGAN model, we modified a little bit the library to make it more optimal for the model. Initally we were having problems with the model, when we tried to use self.disabled_dp, but we had problems with the hardware, because it was so demanding, we even used RunPod, but eventually we settled for a high epsilon value, which was 3000000, which was practically no differential privacy, we concluded that the model with the extreme high epsilon had the highest DQS(which takes into account equally utility, fidelity, privacy and diversity), and had the best parameters, except for the privacy, in which the models with epsilon values of 5 had a slighter better privacy score, but lower DQS. But epsilon values of 1, 3 and 10 had lower privacy values suprinsingly than even the one with extreme epsilon value.

WARNING: THIS CAN CHANGE DEPENDING ON THE RUN, BUT IN ALL RUNS the one with no dp, scores the highest, and always there are epsilon who score higher in privacy (while not being the same). 

An important addition, in the final final, we modify it the fidelity score, initially it was only the qualityreport, but we added the diagnositic report (with a weight of 0.25) to the fidelity score. We thought it was a good idea, due to the fact that in synsynthesizer, there were so moments were the score was different from 100%, due to the outliers in the synthetizer being bigger or smaller than the real data. And we thought it was important to include both, even though the quality report is more important, as we added it a bigger weight of 0.75. We fixed the outliers in the synthetizer, by capping the values to the maximum and minimum of the real data.

In addition in the final version, for categorical columns for diversity, we fixed the aspect treating categories that do not appear in the other dataset, previously we filtered based on the current dataset, and it was obviously broken, now we filter based on the other dataset.
